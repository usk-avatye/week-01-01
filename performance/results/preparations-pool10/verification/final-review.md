# 풀 10 번호 발급 비교 독립 리뷰

판정: 승인. Critical, Important와 Minor 발견 사항 0건. 파일 수정, 서비스 실행과 재측정 없이 읽기로 진행했다.

- 여섯 원본 SHA-256, 요청72,000개 지연, 풀 획득 지연, 잠금 관찰 비율과 PID별 DB CPU를 독립 재계산해 보고서와 일치함을 확인했다.
- 이전 코드의 서버/계약/DB 변경은 max30→10 한 줄이었다. 실제 풀10, 서로 다른 API PID와 스키마6개, 동일한 측정 파일을 확인했다.
- 측정 당시 도구 압축본의 파일 해시는 여섯 manifest와 같았다. 두 구현의 소스 및 컴파일 파일도 측정 해시와 같았다.
- 실제 DB 다섯 테이블의 READ ONLY 전후 행 수 및 전체 내용 해시가 같았다.
- DB CPU 사용률과 요청당 CPU 비용 구분, 포트3000 시연 API의 기존 상태 유지 설명을 원본과 대조했다.

판단에서 제외한 범위와 처리:

- 다른 작업의 UI 및 복구 시연 수정: 이번 비교는 API 번호 준비와 계측 변경이므로 해당 작업에 남겼다.
- 장기 부하: 승인한 실험은 조건당12,000작업과3회 반복이다. 이번 결과는 그 조건에 적용한다.
- 풀30 대비 인과 기여율: 서로 다른 시점의 두 개선율을 빼서 계산하지 않았다. 보고서에 같은 교차 실험이 필요하다고 기록했다.

이전 테스트와 빌드 로그의 통과 결과는 변경 범위에 맞춰 재사용했다.

# Campaign Guard: 캠페인 예산 가드

광고주가 캠페인 예산을 정하고 모의 집행을 요청하는 웹 서비스입니다. 예산을 넘는 집행을 거절하고, 같은 요청을 재전송해도 비용은 한 번만 반영합니다.

Node.js **20.20.2**, TypeScript, Express 5, `pg`, PostgreSQL을 사용합니다. Express 서버가 웹 화면과 API를 함께 제공합니다.

## 실행

프로젝트 루트에서 실행합니다. PostgreSQL 18.4는 개발 의존성에 포함되어 있습니다. 기본 포트는 DB `55432`, 웹 `3000`입니다.

```sh
npm ci
cp .env.example .env
npm run db:start
```

위 터미널을 유지한 채 두 번째 터미널에서 실행합니다.

```sh
npm run db:migrate
npm run db:seed
npm run build
npm start
```

[http://localhost:3000](http://localhost:3000)에서 확인합니다. 코드 변경 후에는 빌드하고 서버를 재시작합니다.

기존 `.env`를 사용 중이면 복사 단계를 건너뜁니다. 외부 PostgreSQL을 사용하려면 `DATABASE_URL`과 `TEST_DATABASE_URL`을 설정합니다. 테스트 DB 이름은 `_test`로 끝나야 합니다. 웹 주소를 바꾸면 `APP_ORIGIN`도 같은 주소로 설정합니다.

## 시연 계정

기본 `DEMO_PASSWORD`는 `Demo-Campaign-2026!`입니다. 가상 광고주와 캠페인으로 시연합니다. 모든 계정은 [로그인](http://localhost:3000/#/login) 화면을 사용하며 DB의 역할에 따라 캠페인 또는 관리자 목록으로 이동합니다.

로그인 상태에서 로그인이나 가입 화면에 접근하면 역할에 맞는 캠페인 목록으로 이동합니다.

| 이메일 | 계정 | 역할 |
| --- | --- | --- |
| advertiser-a@example.test | 모노픽셀 | 광고주 |
| advertiser-b@example.test | 누크리빙 | 광고주 |
| admin@example.test | 관리자 | 관리자 (조회 전용) |

회원가입으로 광고주 계정을 만들 수 있으며 비밀번호는 15~128자입니다. 관리자 계정은 시드로 준비합니다. `db:seed`는 기존 계정과 캠페인을 유지하면서 시연 데이터를 추가하고 이름을 갱신합니다.

## 핵심 동작

- 캠페인은 일시정지 상태로 생성합니다. 일시정지 중에 누적 집행액 이상의 예산 한도로 수정할 수 있습니다.
- 금액을 입력하고 ‘집행 요청’을 누르면 요청 번호 발급, 번호와 금액 보관, 집행 전송을 자동으로 처리합니다. 번호는 PostgreSQL SEQUENCE로 발급하며 비용은 승인 시 반영합니다.
- 총예산과 집행 금액은 1~1,000,000,000원 정수입니다. 운영 중이고 예산이 충분하면 전액 승인합니다. 일시정지 또는 예산 부족이면 비용 없이 거절합니다.
- 같은 캠페인, 번호와 금액의 재전송은 원래 결과와 처리 시각을 돌려줍니다. 같은 번호에서 금액만 바꾸면 409입니다.
- 승인과 거절 결과는 고정됩니다. 조건 변경 후 새 판단은 새 번호로 요청합니다.
- 브라우저는 집행 전 번호와 금액을 보관합니다. 결과가 미확정인 요청에만 ‘결과 확인’과 ‘다시 시도’를 표시하고 같은 번호와 금액을 사용합니다. 조회 결과가 ‘준비’여도 늦은 집행 요청이 도착할 수 있어 번호와 금액을 유지합니다. 확정된 집행 이력은 조회만 제공합니다.
- 관리자는 모든 광고주의 캠페인과 이력을 조회합니다. API에서 역할과 소유권을 검사합니다.

## 미확정 요청 복구 시연

DB 실행 상태에서 다음 명령을 사용합니다. 클라이언트를 빌드하고 시연 서버를 `http://localhost:3001`에서 실행합니다.

```sh
npm run demo:recovery
```

모노픽셀 계정 `advertiser-a@example.test`에 예산 10,000원인 운영 중 캠페인 두 개를 새로 만듭니다. 터미널에 ‘결과 확인’과 ‘다시 시도’ 링크가 표시되며 현재 링크는 `.local/recovery-demo.json`에도 저장합니다.

1. 시연 서버에서 모노픽셀 계정으로 로그인한 뒤 터미널의 ‘결과 확인’ 링크를 엽니다.
2. 금액 1,000원으로 ‘집행 요청’을 누릅니다. 서버가 승인과 비용을 커밋한 뒤 첫 응답을 끊습니다.
3. 미확정 상태와 두 복구 버튼을 확인합니다. 새로고침 후에도 번호와 금액이 유지됩니다.
4. ‘결과 확인’을 눌러 승인 결과, 누적 집행 1,000원과 이력 한 건을 확인합니다.
5. 출력된 ‘다시 시도’ 링크에서 2~3번을 반복하고 ‘다시 시도’를 누릅니다. 승인 결과, 누적 집행 1,000원과 이력 한 건을 확인합니다.

각 캠페인의 첫 성공 집행 응답을 한 번만 끊습니다. 번호 발급, 결과 조회와 후속 재시도 응답은 전달합니다. 시연을 반복하려면 `Ctrl+C`로 종료하고 명령을 다시 실행합니다. 매번 새 캠페인 두 개를 준비합니다. 포트 변경은 `npm run demo:recovery -- --port 3002`로 지정합니다.

## 구조

`app.ts`에서 의존성을 조립하고 기능별 모듈이 HTTP, 업무 판단, SQL, 화면을 맡습니다.

| 경계 | 책임 |
| --- | --- |
| `src/server/auth` | 회원가입, 비밀번호, DB 세션, 역할, CSRF 검사 |
| `src/server/campaigns` | 소유자 캠페인 조회, 예산, 상태 변경 |
| `src/server/executions/decision.ts` | 상태, 예산에 대한 순수 업무 판단 |
| `src/server/executions/service.ts` | 준비, 집행의 트랜잭션 순서 |
| 기능별 `repository.ts` | 매개변수화 SQL과 DB 행 변환 |
| 기능별 `routes.ts` | HTTP 입력과 응답 연결 |
| `src/server/admin` | 관리자 전용 읽기 쿼리와 라우트 |
| `src/contracts` | 서버와 브라우저 사이 DTO, 식별자는 문자열 |
| `src/client/main.ts` | 경로 선택과 화면 조립 |
| `execution-controller`, `execution-flow`, `pending-store` | 통신 조율, 결과 판별, 요청 정보 보관 |
| 나머지 `src/client` 화면 모듈 | 기능별 DOM 렌더링 |

집행과 예산 및 상태 변경은 **캠페인 행 → 집행 행** 순서로 잠급니다. 준비는 소유권 확인 후 새 번호와 PREPARED 행을 저장합니다. 확정된 요청은 기존 결과를 반환하고 준비 상태인 요청만 현재 조건으로 판단합니다. 예산 반영과 결과 저장을 같은 트랜잭션으로 커밋한 뒤 응답합니다.

